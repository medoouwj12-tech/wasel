# واصل (Wasel) | نظام وتطبيق PWA متكامل لنقل وحجز وحضور الطلاب

تطبيق ويب تقدمي احترافي متكامل (**Progressive Web App - PWA**) يعمل كتطبيق حقيقي على الهاتف عبر تقنية **Add to Home Screen / Install App**. يتيح للطلاب تسجيل حساب دائم لمرة واحدة فقط، واستخدام التطبيق يومياً لحجز الرحلات وتسجيل الحضور بضغطة زر واحدة أو عبر مسح رمز **QR Code**.

---

## 🌟 أبرز مميزات النظام

### 1. تطبيق ويب تقدمي حقيقي (PWA - Mobile First)
* **تثبيت التطبيق على الهاتف (Install App)**: يظهر زر وتنبيه ذكي يرشد الطالب لتثبيت التطبيق على هواتف Android و iPhone.
* **أيقونة على الشاشة الرئيسية**: يفتح التطبيق في وضع ملء الشاشة (Standalone) بدون شريط المتصفح، مما يعطي تجربة تطبيق الهاتف الأصلي (Native App).
* **دعم Offline Caching**: حفظ ملفات واجهة المستخدم (App Shell) في Service Worker مع حماية العمليات الحساسة (تسجيل الحضور والـ API) لتعتمد حصرياً على الخادم المباشر لمنع أي تلاعب.
* **دعم شاشات الهواتف والأجهزة اللوحية والحواسيب**: تصميم عصري متوافق بالكامل مع الهواتف الذكية مع شريط تنقل سفلي (Bottom Navigation).

### 2. مفهوم دورة النقل اليومية (Daily Transportation Cycle)
* كل يوم له دورة تشغيل مستقلة تماماً في قاعدة البيانات (`Daily Operations`).
* لكل يوم:
  * رحلات يومية مستقلة (`Daily Trips`).
  * حجوزات يومية مستقلة (`Daily Bookings`).
  * حضور يومي مستقل (`Daily Attendance`).
* **إغلاق اليوم (Close Day)**:
  * عند انتهاء اليوم (تلقائياً في 23:59 أو يدوياً بواسطة الـ Admin)، يتم إغلاق الدورة.
  * يمنع النظام بعد الإغلاق: تعديل الحجوزات، أو تسجيل الحضور المتأخر، أو تغيير الرحلات.
  * تظل كافة بيانات اليوم المحفوظة للأرشيف والتقارير والتحليلات.
* في اليوم التالي: تبدأ دورة جديدة دون التأثير على بيانات الأيام السابقة.

### 3. تجربة الطالب الذكية (Student Experience)
* **تسجيل دائم لمرة واحدة**: الطالب يسجل حسابه لمرة واحدة فقط برقم الهاتف وكلمة المرور ونقطة الركوب المفضلة.
* **جلسة دائمة (Persistent Session)**: لا يحتاج لإعادة تسجيل الدخول كل يوم.
* **الصفحة الرئيسية اليومية**:
  * ترحيب شخصي: "مرحبًا محمد 👋".
  * عرض تاريخ اليوم وحالة الدورة (مفتوحة / مغلقة).
  * بطاقة الرحلة المعينة: خط السير، رقم الأوتوبيس، لوحة المركبة، اسم السائق، نقطة الركوب ووقت الانطلاق.
  * حالة الحضور اللحظية:
    * 🟠 لم يتم تسجيل الحضور بعد
    * 🟢 تم تسجيل الحضور ✓ (مع وقت وتاريخ التسجيل)
* **إثبات الحضور**: الوضع الافتراضي أن يبدأ السائق الرحلة ثم يسجل الصعود بمسح رمز QR أو يدوياً. يمكن للمدير السماح بتأكيد الطالب الذاتي من الإعدادات إذا وافقت سياسة الجهة.
* **رمز الصعود الرقمي (QR Code)**: رمز عشوائي طويل وفريد لكل حجز، ويقبله الخادم لرحلة السائق المعيّنة فقط.
* **الحجز المسبق لرحلة الغد**: حجز مقعد في رحلات الغد مع استعراض نقاط الركوب ونسبة إشغال المقاعد.
* **سجل الحضور الشخصي**: استعراض الرحلات السابقة ونسبة الالتزام بالحضور مع خصوصية مطلقة تمنع الطالب من رؤية بيانات أي طالب آخر.

### 4. تطبيق السائق والمشرف (Driver / Staff App)
* واجهة مخصصة للهاتف للسائقين والمشرفين.
* عرض رحلة اليوم المعينة له، مع عدادات لحظية: (إجمالي الحجوزات، الحاضرون، المتبقون).
* **كاميرا فحص الـ QR (Scan QR)**: مسح رمز الـ QR مباشرة من كاميرا الهاتف لتسجيل حضور الراكب فورياً وتأكيد اسمه ومحطة ركوبه.
* **قائمة الركاب (Manifest)**: مرتبة حسب تسلسل محطات الركوب مع إمكانية تسجيل الحضور اليدوي والاتصال المباشر برقم الطالب.
* **بدء الرحلة وإنهاؤها**: بدء الرحلة يفعّل تسجيل الصعود، وإنهاؤها يعتمد حالة الركاب المتبقين.

### 5. لوحة تحكم الإدارة الشاملة (Admin Dashboard)
* **نظرة عامة والتحليلات**: بطاقات مؤشرات الأداء (إجمالي الطلاب، رحلات اليوم، الحجوزات، الحاضرون، الغائبون، المركبات، السائقون) مع فلترة التواريخ (اليوم، غداً، أمس، مخصص).
* **إدارة دورات الأيام (Daily Operations)**: جدول تفصيلي يوضح كل يوم وحالته ونسبة حضوره مع أزرار إغلاق اليوم وفتحه.
* **إدارة الرحلات (Trips)**: إضافة وجدولة الرحلات ومتابعة عدد المقاعد المحجوزة والمتبقية ومنع الحجز عند امتلاء السعة (FULL).
* **إدارة المركبات (Cars & Buses)**: أوتوبيسات وسيارات وسعات الركاب وحالاتها (متاحة، صيانة، غير نشطة).
* **خطوط ومحطات السير (Routes & Pickups)**: رسم مسار الخط ومحطات الركوب وزمن الوصول لكل محطة.
* **شؤون الطلاب (Students)**: بحث فوري بالاسم أو الهاتف، متابعة نسبة حضور كل طالب، تفعيل وتعطيل الحسابات، وسجل تفصيلي لحضور الطالب.
* **التقارير وتصدير البيانات (Reports)**: تقارير الحضور والغياب مع تصدير فوري إلى **Excel / CSV** متوافق مع اللغة العربية وخيار الطباعة.
* **إعدادات النظام (Settings)**: تعديل أوقات الإغلاق التلقائي، فترات الحجز المسبق، وبيانات الشركة.

## 🛠️ البنية التقنية (Architecture & Tech Stack)

* **Backend**: Node.js + Express REST API (مع دعم Express 5).
* **Database**: SQLite عبر `node:sqlite` مع WAL والمفاتيح الخارجية والمعاملات.
* **Authentication**: JWT (JSON Web Tokens) مع تشفير كلمات المرور عبر `bcryptjs` ونظام صلاحيات RBAC صارم.
* **Frontend**: React 19 + Vite + Tailwind CSS + Lucide Icons + Cairo Font (RTL Native).
* **PWA**: Web App Manifest (`manifest.json`) + Service Worker (`sw.js`) + App Icons (192x192, 512x512, Maskable) + Install Prompt.
* **QR System**: `qrcode.react` لتوليد الأكواد الرقمية + `html5-qrcode` للمسح المباشر بكاميرا الهاتف.

## 🚀 تشغيل النظام

يتطلب المشروع Node.js 22.13 أو أحدث ليتوفر `node:sqlite` من دون علم تشغيل تجريبي. ثبّت تبعيات الجذر والواجهة مرة واحدة:

```bash
npm ci
npm ci --prefix client
```

للتطوير المحلي مع بيانات العرض:

```bash
npm run seed
npm run build
npm start
```

يفتح التطبيق على [http://localhost:5000](http://localhost:5000). لتشغيل واجهة التطوير منفصلةً استخدم `npm run client` وشغّل الخادم في نافذة أخرى باستخدام `npm run server`.

## 🚢 تسليم الإنتاج

1. انسخ `.env.example` إلى `.env` أو أدخل القيم كمتغيرات بيئة في منصة الاستضافة. لا ترفع ملف `.env` أو قاعدة بيانات التطوير إلى مستودع العميل.
2. استخدم قاعدة بيانات جديدة ومجلداً دائماً للبيانات، واضبط `DATABASE_PATH` على ملف SQLite داخل هذا المجلد. بدء الخادم في الإنتاج يرفض استخدام المسار المحلي الافتراضي.
3. عيّن `NODE_ENV=production` و`TZ=Africa/Cairo`، وضع قيمة عشوائية سرية لا تقل عن 32 حرفاً في `JWT_SECRET`. اترك `REQUIRE_STUDENT_APPROVAL=true` حتى يراجع المدير تسجيلات الطلاب.
4. وجّه النطاق إلى الخادم عبر HTTPS؛ الوصول للكاميرا وميزة تثبيت PWA يحتاجان سياقاً آمناً. إذا كانت الواجهة وAPI على نطاقين مختلفين، اضبط `VITE_API_BASE` بعنوان API وأضف أصل الواجهة كاملاً إلى `CORS_ORIGINS`. استخدم `TRUST_PROXY=true` فقط خلف وكيل عكسي موثوق.
5. ثبّت التبعيات وابنِ الواجهة ثم أنشئ حساب المدير الأول. بيانات العرض محظورة في بيئة الإنتاج.

```bash
npm ci
npm ci --prefix client
npm run build
npm run bootstrap:admin
npm start
```

املأ `INITIAL_ADMIN_NAME` و`INITIAL_ADMIN_PHONE` و`INITIAL_ADMIN_PASSWORD` قبل `bootstrap:admin`، واحذف كلمة المرور من بيئة التشغيل بعد إنشاء المدير. سجّل الدخول وأضف بيانات الشركة، وخطوط السير، ونقاط الركوب، والمركبات، والسائقين، والرحلات. خصص مساحة قرص دائمة للملف ونسخاً احتياطية دورية، وشغّل نسخة واحدة من خادم SQLite لكل قاعدة بيانات.

قبل التسليم، استبدل بيانات الشركة وبيانات العرض، وراجع نصوص الخصوصية وموافقة ولي الأمر وإجراءات دعم الطوارئ بما يناسب الجهة التي ستستخدم النظام.
